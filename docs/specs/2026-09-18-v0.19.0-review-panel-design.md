# v0.19.0 — Configurable review panel with unanimous consensus; reaping orphaned checkouts

**Status:** draft (spec round 1)
**Feature:** v0.19.0-review-panel

## Problem

Every review today is exactly two voices: Claude first, then one external reviewer (Codex by
default). The user wants a third independent voice on **planning**, where slowness is acceptable,
without slowing execution reviews, and without it being a tiebreaker: each member reviews
independently and the panel must reach unanimous consensus. Separately, a run that crashes can
leave checkouts behind; nothing reports or removes them.

Measurements taken while designing this (2026-09-18), because they decide the design:

| Probe | Input tokens | Cached | Note |
| --- | --- | --- | --- |
| `codex exec`, trivial prompt | 37,612 | 31,488 (84%) | OpenAI caches the harness prefix automatically |
| `codex exec resume <id>` same session | 49,416 | 43,136 (87%) | more total input, same uncached (~6.3K vs ~6.1K cold) |
| `agy -p`, trivial prompt | 13,983 | **0** | Gemini via agy reports `cache_read_tokens: 0` |
| `agy -p --conversation <id>`, 2nd turn | 28,182 | **0** | re-sends the whole history, uncached |

Two consequences: resuming a writer session does not reduce usage (so it is not built here), and a
**continued Gemini conversation gets more expensive every round with no caching**, so a Gemini panel
member must not accumulate a conversation across rounds.

## Goals

<<<GOALS>>>
- Goal 1: The set of external reviewers is configurable per review phase (planning vs execution),
  and with no configuration the behaviour is exactly today's: Claude plus one external reviewer.
- Goal 2: When a phase has more than one external reviewer, every member reviews the same artifact
  independently (no member sees another's verdict within a round), and a round passes only when
  Claude and every member approve the same artifact version; any blocking finding from any member
  sends it back.
- Goal 3: Consensus is reached across rounds, not by vote: each member sees every other member's
  findings in the next round and may agree, extend or push back; there is no majority rule and no
  tiebreaker. The existing round cap and escalation to the user still apply.
- Goal 4: A configured panel never silently shrinks: an unavailable or unauthenticated member halts
  the review with a named reason instead of proceeding with fewer voices.
- Goal 5: A Gemini member's per-round cost does not grow with the round number.
- Goal 6: `doctor` reports checkouts left behind by crashed runs, and a reap command removes the
  ones that are provably safe to remove while never deleting a checkout that may hold unmerged work
  or a halted run's evidence.
<<<END_GOALS>>>

## Non-goals

- Resuming writer sessions (measured: no usage saving).
- Changing the existing single-reviewer `agy` transport's conversation reuse (see Deferred).
- Majority voting, weighted votes, or a tiebreaker of any kind.
- Automatically deleting dirty or unmerged checkouts.

## Design

### 1. Configuration

`.codex-paired/project.json` (local; `.codex-paired/` is gitignored, so it never ships to other
users) gains an optional block:

```json
"review_panel": {
  "planning": [ { "cli": "codex" }, { "cli": "agy", "model": "gemini-3.8-flash-high" } ],
  "review":   [ { "cli": "codex" } ]
}
```

- Each entry is `{ "cli": "codex" | "agy", "model"?: string }`. When `model` is absent, it resolves
  from the phase's model role (`planning` or `review`) if that role's `cli` matches, otherwise from
  the CLI's default for that role (Codex: the role's default model; agy: `gemini-3.8-flash-high`).
  Effort follows the existing rules (Codex from the role; agy from the model-id suffix).
- **Default when the block or a phase is absent: `[ { "cli": <that role's cli> } ]`** — one
  external reviewer, which is today's behaviour byte for byte (Goal 1).
- Validation reuses `validateModelsBlock`-style errors: a non-array, an empty array, an unknown
  `cli`, a duplicate **(cli, resolved model) pair** within one phase, or an invalid model token →
  `models-config-malformed` with the path. The same CLI with two different models is allowed (for
  example two Codex models): they are different models, so they are independent voices. The same CLI
  and model twice is not, and is rejected.
- **Self-review warning.** If a member's resolved model equals the `implement` role's model, the
  panel is reviewing code written by the same model. That is permitted (the user's call) but
  `review-panel` and `doctor` print a warning naming the member, because it is a weaker check than a
  different model.
- `CODEX_PAIRED_REVIEW_PANEL_PLANNING` / `_REVIEW` env overrides take a comma-separated CLI list
  (e.g. `codex,agy`) and win over the file, matching the existing env precedence.
- New CLI verb `review-panel --phase planning|review --repoRoot <repo> [--format json]` prints the
  resolved members `[{ cli, model, effort }]`; exit 0, exit 2 on a config error.

### 2. One panel round

For a round on artifact version V (a spec or plan file's content hash, or a commit SHA). Every
member's verdict records the V it reviewed; if any member reviewed a different V (the artifact
changed mid-round), the round is void and re-run, so unanimity is always about one version:

1. Claude writes its own findings first, as today.
2. Every panel member is dispatched **in parallel** with the same prompt: the artifact, the goals,
   Claude's findings, and (from round 2) the aggregated findings of **all** members from the previous
   round, labelled by member. No member sees another member's verdict for the current round.
3. Each member returns the standard verdict block (`status`, `critique` with rubric evidence,
   `deferred`), parsed with `parseVerdict`.
4. **Unanimous:** the round is SHIP only if Claude and every member returned SHIP for version V.
   Otherwise REVISE, and the next round's prompt carries every member's blocking findings. Deferred
   items are batched as today.
5. Round cap 7 and escalation to the user are unchanged.

Members run in parallel, so a three-voice round costs roughly the slowest member's latency, not the
sum.

### 3. Member transports

- **Codex member:** keeps one persistent MCP thread per feature and phase, exactly as today
  (measured 84–87% of input cached).
- **Gemini member (`agy`):** a **fresh conversation every round** in a throwaway checkout of V,
  seeded with a compact replay: the goals, the round number, and every prior round's blocking
  findings from all members with how each was resolved. It never continues a prior conversation,
  because a continued agy conversation re-sends the entire history uncached (Goal 5). The replay is
  bounded: prior rounds' findings only, never prior full responses.

### 4. Availability

Before round 1, each member is resolved and checked with the existing availability detector (binary
present and auth probe passing). Any unavailable member halts the review with
`panel-member-unavailable` naming the member and the fix (install, sign in, or remove it from
`review_panel`). The panel is never reduced silently (Goal 4). A member that fails mid-review
(timeout, auth expiry, parse failure) halts the same way after the existing retry rules; the round is
not decided with fewer voices.

### 5. Recording

Rounds keep their existing fields. `round.codex` continues to mean "the external verdict" and is
SHIP only when every member is SHIP, so every existing reader keeps working. An additive
`round.panel: [{ member, cli, model, status, thread_or_conversation }]` records each voice, and each
member gets its own verification audit (`side: <member id>`). The SHIP-audit gate requires an audit
from every member on a panel SHIP. `docs/public-api.md` is updated for the new verb and the additive
round field (a minor, additive change under the semver policy).

### 6. Orphaned checkouts

Three kinds of leftover exist:

| Kind | Where | Safe to remove automatically? |
| --- | --- | --- |
| stale git worktree metadata | `git worktree list --porcelain` entries whose directory is gone | yes — `git worktree prune` |
| throwaway review checkouts | `cps-review-*` under the temp dir, created by `withReviewCheckout` | yes, when no live process has its cwd inside and it is older than 1 hour |
| implementation worktrees | `.git-worktrees/*` | only when **clean**: no uncommitted changes, and the branch has no commits that are not reachable from the integration branch |

- **Liveness** reuses the v0.18.0 ownership discovery (`lsof -a -d cwd` on macOS, `/proc/<pid>/cwd`
  on Linux) extracted from the fresh-clone smoke into a shared helper: a checkout with any live
  process inside is never touched.
- **`doctor`** gains a `worktrees` check: `pass` when nothing is found, `warn` listing each leftover
  with its kind, age and, for implementation worktrees, whether it is clean, dirty or unmerged. It
  never fails.
- **`worktree-reap`** CLI verb: dry run by default (prints what it would do, exit 0); `--apply`
  prunes metadata, removes stale review checkouts, and removes clean orphaned implementation
  worktrees and their merged branches. Dirty or unmerged implementation worktrees are **never**
  removed: they are listed with the reason, because autopilot deliberately leaves them after a halt
  as evidence and they may hold work that exists nowhere else. Removing one stays a manual decision.

## Deferred

- The existing single-reviewer `agy` transport (`reviewer-thread-reply`) continues its conversation
  across rounds and therefore pays the growing uncached history measured above. Switching it to
  fresh-per-round changes existing behaviour; do it in its own release after the panel's Gemini
  member has proven the replay approach.
- A panel in the execution phase of autopilot's fan-out (two-disjoint) path; the post-merge panel
  there already has its own rules.
