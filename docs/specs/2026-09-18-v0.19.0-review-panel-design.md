# v0.19.0 — Configurable review panel with unanimous consensus; reaping orphaned checkouts

**Status:** draft (spec round 2 — revised after the three-voice panel's round 1: Claude, Codex GPT-6 Astra xhigh, Gemini 3.8 Flash high)
**Feature:** v0.19.0-review-panel

## Problem

Every review today is exactly two voices: Claude first, then one external reviewer (Codex by
default). The user wants a third independent voice on **planning**, where slowness is acceptable,
without slowing execution reviews, and without it being a tiebreaker: each member reviews
independently and the panel must reach unanimous consensus. Separately, a run that crashes can
leave checkouts behind; nothing reports or removes them.

### What was measured, and what it does and does not show

| Probe (2026-09-18) | Input tokens | Cached / cache-read | Wall clock |
| --- | --- | --- | --- |
| `codex exec`, trivial prompt | 37,612 | 31,488 cached (84%) | seconds |
| `codex exec resume <id>`, same trivial session | 49,416 | 43,136 cached (87%) | seconds |
| `agy -p`, trivial prompt | 13,983 | 0 | seconds |
| `agy -p --conversation <id>`, trivial 2nd turn | 28,182 | 0 | seconds |
| **`agy -p`, this spec's round-1 review (real, agentic)** | **897,196** | **3,996,046 cache-read** | **405 s** |

What this supports: OpenAI caches the Codex harness prefix automatically; a trivial resumed Codex
session carries more total input with a similar uncached amount; a real Gemini review is agentic
and caches heavily *within* one review (many internal turns), but is also expensive in absolute
terms — about 0.9 M input and 0.94 M total tokens for one round of one spec.

What it does **not** support, and this spec no longer claims: that Gemini never caches (the trivial
probes were misleading; the real review cache-read ~4 M tokens), or that resuming a writer never
saves usage in a real fix pass (only a trivial task was measured). The Gemini member's design below
therefore rests on **bounding cross-round history** (Goal 5), not on a caching claim.

**Cost disclosure.** A three-voice planning panel adds roughly one Gemini review's cost to every
planning round. That is why the shipped default stays one external reviewer and enabling the panel
is an explicit choice.

## Goals

<<<GOALS>>>
- Goal 1: The set of external reviewers is configurable per review phase (planning vs execution),
  and with no configuration the behaviour is exactly today's: Claude plus one external reviewer.
- Goal 2: When a phase has more than one external reviewer, every member reviews the same artifact
  independently (no member sees another's verdict within a round), and a round passes only when
  Claude and every member approve the same artifact version; any blocking finding from any member
  sends it back.
- Goal 3: Consensus is reached across rounds, not by vote: each member sees every other member's
  findings in the next round and may agree, extend or push back; there is no majority rule and no
  tiebreaker. The existing round cap and escalation to the user still apply.
- Goal 4: A configured panel never silently shrinks: an unavailable or unauthenticated member halts
  the review with a named reason instead of proceeding with fewer voices.
- Goal 5: A Gemini member's per-round cost does not grow with the round number.
- Goal 6: `doctor` reports checkouts left behind by crashed runs, and a reap command removes the
  ones that are provably safe to remove while never deleting a checkout that may hold unmerged work
  or a halted run's evidence.
<<<END_GOALS>>>

## Non-goals

- Resuming writer sessions (not measured on a real fix pass; out of scope here).
- Changing the existing single-reviewer `agy` transport's conversation reuse (see Deferred).
- Majority voting, weighted votes, degraded quorum, or a tiebreaker of any kind.
- Automatically deleting dirty, unmerged, detached-unreachable, or evidence-bearing checkouts.
- Multi-member panels on the two-disjoint fan-out or hybrid routes (they halt; see §7).

## Design

### 1. Configuration

`.codex-paired/project.json` (local; `.codex-paired/` is gitignored, so it never ships to other
users) gains an optional block:

```json
"review_panel": {
  "planning": [ { "cli": "codex" }, { "cli": "agy", "model": "gemini-3.8-flash-high" } ],
  "review":   [ { "cli": "codex" } ]
}
```

- Each entry is `{ "cli": "codex" | "agy", "model"?: string }`. When `model` is absent it resolves
  from the phase's model role (`planning` or `review`) if that role's `cli` matches, otherwise from
  the CLI's default for that role (Codex: the role's default model; agy: `gemini-3.8-flash-high`).
  Effort follows the existing rules (Codex from the role; agy from the model-id suffix).
- **Default when the block or a phase is absent: `[ { "cli": <that role's cli> } ]`** — one
  external reviewer, today's behaviour byte for byte (Goal 1).
- Validation (`models-config-malformed`, naming the path): non-array; empty array; unknown `cli`;
  a duplicate **(cli, resolved model)** pair within a phase (the same CLI with two different models
  is allowed — different models are independent voices; the same model twice is not); an invalid
  model token.
- **Self-review warning:** if a member's resolved model equals the `implement` role's model, the
  panel is reviewing code written by the same model. Permitted, but `review-panel` and `doctor`
  print a warning naming the member.
- Env overrides `CODEX_PAIRED_REVIEW_PANEL_PLANNING` / `_REVIEW`: comma-separated CLI list
  (`codex,agy`), winning over the file per the existing precedence.
- New CLI verb `review-panel --phase planning|review --repoRoot <repo> [--format json]` prints the
  resolved roster `[{ member_id, cli, model, effort }]`; exit 0, exit 2 on a config error.
  `member_id` is `<cli>:<model>`, stable and unique within a phase.

### 2. One panel round

A round reviews artifact version **V**: a commit SHA for code, or `sha256:` of the file content for
a spec or plan.

1. Claude writes its own findings first, recording V.
2. Every member is dispatched **in parallel** with the same prompt: the artifact, the goals,
   Claude's findings, and (from round 2) the bounded replay of §3. No member sees another member's
   verdict for the current round.
3. Each member returns the standard verdict block, which gains a **required `version:` field**
   naming the V it reviewed. `parseVerdict` returns `version`; a verdict with a missing `version`,
   or a `version` different from the round's V, is treated as a failed member turn (§4), never as a
   vote.
4. **Unanimous:** the round is SHIP only if Claude and every roster member returned SHIP on the same
   V. Any REVISE, from anyone, sends it back; the next round's prompt carries every member's blocking
   findings labelled by member. Deferred items are batched as in v0.18.1.
5. Round cap 7 and escalation to the user are unchanged.

The strict-unanimity reducer is new code. The existing panel aggregator
(`panel/verdict-aggregator.js`) is **not** reused for the decision, because it permits degraded
quorum (`degraded-N-proceeds` returns `panel-SHIP` when one member failed to parse), which would let
the panel shrink silently. Its dispatch fan-out and member snapshotting (`panel/dispatcher.js`) are
reused.

### 3. Member transports and the bounded replay

- **Codex member:** one persistent MCP thread per feature, phase and `member_id` (two Codex models
  get two threads), as today.
- **Gemini member (`agy`):** a **fresh conversation every round** in a throwaway checkout of V,
  seeded with a **fixed-budget replay** so that cross-round history cannot grow (Goal 5):
  - always: the goals and the round number;
  - every **still-unresolved** blocking finding, each with the member who raised it and its current
    status;
  - the **previous round's** member-labelled findings only;
  - earlier resolved findings as a count, never as text.
  The replay has a hard budget of **12,000 characters**. If the unresolved findings alone exceed it,
  the review halts with `panel-replay-overflow` — it never truncates, because truncation would
  silently drop a finding. A test holds the artifact constant and drives rounds 1 through 7,
  asserting the replay never exceeds the budget and never grows when the unresolved set is constant.

### 4. Availability and member failure

Before round 1 every member is resolved and checked with the existing availability detector
(binary present, auth probe passing: `codex login status`, `agy models`). Any unavailable member
halts the review with `panel-member-unavailable`, naming the member and the fix (install, sign in,
or remove it from `review_panel`). A member that fails mid-round — timeout, auth expiry, parse
failure, missing or wrong `version` — halts the same way after the existing retry rules. A round is
never decided with fewer voices than the roster (Goal 4).

### 5. Recording and the append gate

- **Roster.** At round 1 the resolved roster is persisted in the sidecar as
  `panel_roster[<phase>] = [{ member_id, cli, model, effort }]`. The roster is fixed for the life of
  the phase; changing `review_panel` mid-phase halts with `panel-roster-changed` instead of mixing
  rosters.
- **Round record.** A round in a phase that has a roster must carry
  `round.panel: [{ member_id, cli, model, version, status, thread_or_conversation }]` and
  `round.claude_version`.
- **The append gate (`appendRound`) enforces unanimity at the boundary**, not the caller:
  - `round.panel` present, with **exactly one** entry per roster member — none missing, none extra,
    no duplicates — else rejected;
  - every entry's `version` and `round.claude_version` equal, else rejected (the round is void);
  - `round.codex` is **derived**: SHIP iff every member is SHIP. A caller-supplied `round.codex`
    that disagrees with the derivation is rejected, so every existing reader of `round.codex`
    (including `scripts/v0.9.0-release-gate.sh`) sees a value it cannot have been handed wrongly;
  - omitting `round.panel` in a phase that has a roster is rejected.
- **The SHIP-audit gate (`assertRoundShipBacked`)**, today hard-coded to sides `['claude','codex']`,
  requires on a panel SHIP a qualifying verification audit for `claude` **and for every roster
  `member_id`**. With no roster it behaves exactly as today.
- **Public API** (`docs/public-api.md`), all additive under the semver policy: the verbs
  `review-panel` and `worktree-reap` enter the `cli-verbs` inventory with cases; the sidecar
  `top_level_keys` gains `panel_roster`; the `rounds.items` shape (currently `additional: false`)
  gains optional `panel` and `claude_version`; the verdict format documents `version:`. The
  module/input digests refresh as usual.

### 6. Orphaned checkouts

**Inventory comes from git's own registry**, `git worktree list --porcelain`, so every registered
checkout is found wherever it lives — `.git-worktrees/*`, the fan-out's
`.codex-paired/worktrees/**`, and review checkouts — plus stray `cps-review-*` directories under the
temp dir that git no longer knows about.

A checkout is **reapable only if every applicable condition holds**, re-evaluated immediately
before each removal (not only at listing time):

1. **Not in use.** Ownership discovery (the v0.18.0 helper, extracted from the fresh-clone smoke into
   a shared module: `lsof -a -d cwd` on macOS, `/proc/<pid>/cwd` on Linux) finds no process whose
   cwd is inside it. If discovery is **incomplete** (the tool is missing, or any entry returned a
   permission error), nothing is removed: unknown means keep.
2. **No unique commits.** Its `HEAD` — branch or detached — is reachable from some ref other than the
   checkout itself (`git for-each-ref` over branches and tags, excluding this checkout's own branch).
   A checkout holding the last reference to a commit is never removed.
3. **No uncommitted work.** `git status --porcelain` is completely empty: no modified, staged, **or
   untracked** files. Ignored files are allowed only under the known-regenerable paths
   (`node_modules/`, `.tia-cache/`); any other ignored file means keep.
4. **Not evidence.** No sidecar in the repository records a halt that names this checkout's path, and
   the fan-out's `keepForensics` marker is absent. Autopilot deliberately leaves worktrees after a
   halt; those are never removed automatically.
5. **Old enough.** Older than 1 hour for review checkouts, 24 hours for implementation checkouts.

Review checkouts are throwaway by contract (`withReviewCheckout` creates them detached at an existing
commit and overlays copies of the user's spec/plan); nothing in them is work product. They still pass
conditions 1, 2 and 5; conditions 3 and 4 do not apply to them.

**Stale metadata** (a registered worktree whose directory is gone) is pruned only when condition 2
holds for its recorded `HEAD`: `git worktree prune` drops that reference, so pruning an entry that
held the last reference to a detached commit could make it collectable. Otherwise it is reported and
kept.

- **`doctor`** gains a `worktrees` check: `pass` when nothing is found, otherwise `warn` listing each
  leftover with its kind, age, and which condition keeps it. It never fails.
- **`worktree-reap`**: dry run by default (prints the plan, exit 0); `--apply` performs only the
  removals whose conditions all still hold at the moment of removal, prints what it removed and what
  it kept and why, and exits 0; exit 2 on a usage error. There is no flag that removes a kept
  checkout: removing one stays a manual decision.

### 7. Unsupported routes halt

A `review` roster with more than one member is supported for single-implementer reviews (SDD Step C
and autopilot Phase C). On the two-disjoint fan-out route — whose post-merge review requires exactly
two reviewer entries (`implementer/post-merge-review.js`) — and on the hybrid route, a multi-member
`review` roster halts with `panel-unsupported-route` **before** execution starts, instead of
proceeding through a gate that would omit configured voices.

## Deferred

- The existing single-reviewer `agy` transport (`reviewer-thread-reply`) continues its conversation
  across rounds. Whether that is costlier than fresh-per-round for a real review is unmeasured; revisit
  with full-round measurements once the panel's replay approach has run.
- Replay/recovery integration details (`buildReplayContext`, `composeSeedPrompt`) for per-member
  findings — plan-level detail once the durable contract above is fixed.
- Cherry-pick awareness in `worktree-reap`: autopilot integrates by cherry-pick, so an integrated
  branch can look unmerged by SHA reachability and be kept. Safe (it errs toward keeping); a
  `git patch-id` or sidecar-`shipped` check can relax it later.
- Model syntax in the env override (`codex:gpt-5.6-sol,agy:…`).
- Multi-member panels on the two-disjoint and hybrid routes.
