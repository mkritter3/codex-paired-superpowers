# v0.18.0 — Robustness for other people's machines: type checking, stable public API, portability

**Status:** draft (spec round 7 — revised after Codex rounds 1–6)
**Feature:** v0.18.0-robustness

## Problem

v0.16.0 and v0.17.0 were built and reviewed on one machine. The review rounds surfaced a pattern:
most accepted findings were *type-shaped* (wrong-typed evidence fields accepted as success,
call sites dropping an argument, a config value with the wrong shape). The codebase is plain
JavaScript with no type checking (no `tsconfig`, no `@ts-check`, sparse JSDoc), so nothing but
tests catches these. Meanwhile a person installing the plugin elsewhere has no CI signal that
the suite passes on their OS/Node, no written statement of what surface is stable, one path in
the README pointing at the author's home directory, and no way to verify a fresh clone works
before their first real run.

## Goals

<<<GOALS>>>
- Goal 1: `npm test` fails when a checked module violates its declared JSDoc types; the set of
  checked modules covers every module that defines a public contract (below) and grows by an
  explicit allowlist, never silently.
- Goal 2: There is one document, `docs/public-api.md`, naming exactly what is stable for users
  (skills and their arguments; `lib/codex-bridge/cli.js` verbs, flags, stdout shapes and exit codes;
  `scripts/codex-exec-with-status.sh` flags, exit codes and status-file fields;
  `bin/codex-paired-doctor` output; `.codex-paired/project.json` schema; sidecar `version`), with a
  semver policy, and a contract test that fails when any of those change without the doc changing.
- Goal 3: A GitHub Actions workflow runs the default test tiers plus type checking on Ubuntu and
  macOS across the supported Node majors on every push and pull request; the README badge and
  Prerequisites section state the supported platforms (Linux, macOS; Windows unsupported) and
  Node range, and `doctor` reports an unsupported platform or Node version as FAIL.
- Goal 4: A fresh-clone smoke (`npm run test:fresh-clone`) clones the repository into a temp
  directory, runs `doctor` and one end-to-end fake-CLI implementer + reviewer cycle there, and
  passes; it runs in CI.
- Goal 5: Behaviour for existing users is unchanged: no skill, verb, flag, exit code, status-file
  field or config key changes meaning in this release (additions only).
<<<END_GOALS>>>

## Non-goals

- Migrating to TypeScript, `.d.ts` publishing, or a build step.
- Windows support.
- Changing the review pipeline, model roles, or transports.
- Type-checking `skills/*.md` code snippets (they are prose); structural tests keep covering them.
- Replacing or tightening the `project.json` loader's validation (see `## Deferred`).

## Design

### 1. Gradual JSDoc type checking (Goal 1)

**Scope is explicit, per file, and cannot expand through imports.**

- `tsconfig.json`: `allowJs: true`, **`checkJs: false`**, `noEmit`, `strict: true`,
  `module: nodenext`, `moduleResolution: nodenext`, `target: es2022`, `types: ["node"]`,
  `skipLibCheck: true`. With `checkJs: false`, `tsc` reports **semantic** diagnostics only in
  JavaScript files that carry a `// @ts-check` pragma. The guarantee is precisely *explicit
  JavaScript semantic-checking scope*: an imported unmarked module contributes its types but no
  semantic diagnostics; an imported module with a **syntax** error still fails (TS1109 — wanted);
  and an imported module that carries `// @ts-check` **is** checked even if unlisted — which is
  why the runner reconciles the effective program against the allowlist (next bullet).
- `typecheck.allowlist.json` = `{ "version": 1, "files": [ "lib/codex-bridge/models.js", … ] }`
  (sorted, repo-relative). It is the single source of truth.
- `scripts/typecheck.mjs` (the runner, `npm run typecheck`): reads the allowlist, verifies each
  listed file exists and its first non-shebang line is `// @ts-check`, builds the program via the
  TypeScript API (`ts.createProgram` with `rootNames` = allowlist, `extends`-equivalent options
  from `tsconfig.json`), then reconciles **the effective program**: every JavaScript source file
  in `program.getSourceFiles()` (excluding `node_modules` and declaration files) that carries
  `// @ts-check` must be in the allowlist, wherever it lives (`lib/`, `scripts/`, `bin/`,
  `tests/`, …). Any unlisted `@ts-check` file reached through imports, or any repo file under
  `lib/`, `scripts/`, `bin/` carrying the pragma without being listed, is exit 2 ("allowlist
  inconsistency") — the "never silently" rule in both directions. Then it reports the program's
  diagnostics and exits 1 if any. `npm test` runs it via `pretest` (once; CI does not call it a
  second time).
- **Negative fixture:** `tests/typecheck/fixtures/bad-types.js` (`// @ts-check` + one deliberate
  type error) and `tests/typecheck/runner.test.js`, which invokes the runner with an alternate
  allowlist containing that fixture and asserts non-zero exit with the expected diagnostic, and
  with an allowlist naming a file that lacks the pragma and asserts the runner refuses (exit 2).
  Scope tests: (i) an allowlisted file importing an *unmarked* fixture with a semantic type error
  passes; (ii) an allowlisted file importing an unlisted fixture that carries `// @ts-check` fails
  with exit 2 naming that file; (iii) an imported fixture with a syntax error fails with exit 1.
- **Public-surface → owner inventory** (also the allowlist seed; every owner is a whole file):

  | Public surface | Owner modules (checked) |
  | --- | --- |
  | `cli.js` verbs, flags, stdout shapes, exit codes | `lib/codex-bridge/cli.js` (shebang kept on line 1, pragma on line 2) |
  | model roles / `models` config | `lib/codex-bridge/models.js`, `lib/codex-bridge/project-config.js` |
  | sidecar schema, rounds, audits, thread config | `lib/codex-bridge/sidecar.js`, `lib/codex-bridge/thread-recovery.js`, `lib/codex-bridge/reviewer-thread.js` |
  | wrapper status file consumers | `lib/codex-bridge/dispatch-status.js` |
  | doctor JSON envelope | `lib/codex-bridge/availability/doctor-report.js` |
  | worktrees / review checkout | `lib/codex-bridge/worktree.js` |
  | subprocess lifecycle + adapters | `lib/codex-bridge/cli-harness/process-lifecycle.js`, `cli-harness/adapters/codex.js`, `cli-harness/adapters/agy.js` |
  | direct-CLI attempt evidence | `lib/codex-bridge/implementer/codex-cli-dispatch.js`, `lib/codex-bridge/implementer/types.js` (existing typedefs, reused) |

  Shared shapes not already in `implementer/types.js` go in `lib/codex-bridge/types.js` as
  `@typedef`s (ModelRole, RoleConfig, StatusFile, Sidecar, Round, Audit, ThreadConfig,
  ReviewerTurnResult, HaltEnvelope, DoctorReport). Casts (`/** @type {X} */ (v)`) are allowed at
  I/O boundaries only where a runtime validation already exists on the same value; a cast is never
  a substitute for boundary validation.
- Dev dependencies `typescript` (pinned minor) and `@types/node` (pinned to the **20.x** line,
  the minimum supported runtime). They are **not vendored**: `.gitignore` gains
  `node_modules/typescript/`, `node_modules/@types/`, and `package-lock.json` records them.
  Runtime deps stay vendored exactly as today.

### 2. Public API contract (Goal 2, Goal 5)

- `docs/public-api.md` is the contract. Every stable item is described in prose **and** pinned in
  a fenced block ```` ```json public-api:<section> ````. Sections and what each pins:
  - `skills`: for each user-invocable entry point: the skill name, its slash command(s) from
    `commands/*.md` (`name`, `argument-hint`), and the argument names as documented in the
    skill body's input section. Skills have **no** structured argument frontmatter today, so the
    contract test extends the existing command/body structural checks in
    `tests/skills/skill-structure.test.js` (which already parse `commands/*.md` and skill bodies)
    rather than assuming frontmatter metadata.
  - `cli-verbs`: for **every** verb of `lib/codex-bridge/cli.js`: name, flags (name, required,
    value type), stdout shape (top-level field names and JSON types, e.g.
    `reviewer-thread-open → { threadId: string, content: string, usage: object|null, ok: boolean, exit: number, status: string, warnings: string[] }`), exit codes and their meaning.
  - `wrapper`: `scripts/codex-exec-with-status.sh` flags (`--model-role`, `--repo-root`, `--cwd`,
    `--`), exit codes **`0`, `64` (usage), `74` (status write failure), `78` (model-role config
    error), `129` (HUP), `130` (INT), `143` (TERM), child exit passthrough**, and the status-file
    field set with types and lifecycle (`state started|exited`, `cli`, `cwd`, snapshot fields, …).
  - `doctor`: the JSON envelope (`summary`, `checks[]` record fields with `status ∈ pass|warn|fail`,
    `availability`) and the check names, including the new `platform` check; **and** the stable
    parts of the human output and exit behaviour: exit 0 when no check is `fail`, exit 1 otherwise;
    one line per check prefixed by its status token; the `--json` flag. Line wording is not stable.
  - `project-config`: the **embedded** JSON Schema of `.codex-paired/project.json` **shape** as
    accepted today (inline in the block; no external file) — and, separately, the loader's
    **runtime** behaviours that are part of the contract but that a schema cannot express: `version`
    values accepted, unknown top-level keys ignored, `null` optional blocks (`models`,
    `codex_dispatch`, `mailbox`) allowed, defaults applied, environment-dependent failures (e.g. a
    login profile whose password env var is unset → the existing config error), and the error codes
    with their precedence (`missing-field:version` first, …). The block has two keys: `schema` and
    `runtime` (a list of `{ case, input, env?, expect: { ok: true, config: <normalized values to
    pin, incl. applied defaults> } | { error: <code> } }` fixtures — a changed default keeps
    `ok: true` but fails on `config`).
  - `sidecar`: the sidecar `version` and the top-level keys.
  - `semver`: policy — breaking change to a `stable` item → major; additions → minor; anything under
    `lib/` **other than `lib/codex-bridge/cli.js`** is internal and may change in a patch.
  Each item carries `stability: stable|experimental` and `since`.
- `tests/contract/public-api.test.js` parses the doc's fenced blocks with a strict parser (unknown
  section, duplicate section, or unparseable JSON fails) and compares each against **observed**
  behaviour, not against the source's own declarations:
  - `cli-verbs`: `cli.js` executes its dispatcher at import time and exports no table, so
    enumeration uses the **existing** unknown-verb output (`node cli.js __unknown__` prints
    `available: …` and exits 2 — that line is itself part of the contract). The doc's `cli-verbs`
    block is a **coverage inventory**: for every verb, every flag, every output *variant* (e.g.
    `model-role --format json|flags|mcp`; `anchor-read` → JSON or empty stdout; reviewer verbs →
    success shape / failure shape exit 1 / usage exit 2) and every exit outcome carries a named
    `case` with an `invocation` (args, stdin, env, fixture setup keyword) and an `expect`
    (stdout kind `json|text|empty`, field names + JSON types incl. optional fields and nested
    public shapes, exit code). The test executes **every** case via `spawnSync` against the fake
    CLIs / temp repos and asserts the expectation.
    **Independent discovery.** `cli.js` has no flag registry (`parseArgs` accepts any key), so the
    surface is extracted statically by `scripts/cli-surface.mjs` using the TypeScript AST
    (`typescript` is a dev dep): for each verb handler in the dispatch table it collects (1) flag
    names from the handler's destructured parameter (`{ specPath, role, … }`) and from `args.<key>`
    / `args['<key>']` member accesses, (2) exit codes from `process.exit(<int literal>)`, (3) stdout
    field names from `process.stdout.write(JSON.stringify({ … }))` object literals (top-level keys,
    including shorthand and spread-free literals). Any handler that reads `args` in a pattern the
    extractor cannot follow (computed key, spread, passing `args` whole to another module) is
    reported as `unsupported-extraction` and the inventory must carry an explicit
    `"manual": { "reason": … }` entry for that verb, so opacity is visible, not silent. The
    contract test asserts every extracted flag / exit / field of every verb has at least one
    inventory case ("uninventoried surface"), and the extractor's own tests cover each supported
    pattern.
    **Backstop: module digests over the CLI's dependency closure.** Static extraction cannot
    model every behaviour (a new `--format text` branch in `model-role` changes no flag, exit
    literal or JSON key; a changed top-level constant such as `MESSAGE_ID_RE` changes no handler;
    a changed imported producer such as `mcpCallConfig` in `models.js` changes nothing in
    `cli.js` at all). Selected-node digests therefore cannot be the boundary. The `cli-verbs`
    block pins `"module_digest": { "<repo-relative path>": "sha256:…" }` for **every module in
    the repository-local import closure of `lib/codex-bridge/cli.js`** (derived automatically from
    the TypeScript program's import graph — static `import`/`export … from` and string-literal
    dynamic `import()` — excluding `node_modules`; a new import joins the closure, and therefore
    the pinned set, by construction). **Non-literal module loads** (`import(<expr>)`,
    `createRequire`, `require.resolve`, `import.meta.resolve`, `eval`, `new Function`) are
    detected by the same AST walk; each one must be covered by an **explicit expansion rule** in
    the block's `"expansions"` list or the check fails with "unresolved module load at
    <path>:<line>". Today there is exactly one: `cli-harness/adapters/registry.js` loads adapters
    by computed path, so its rule is `{ "site": "lib/codex-bridge/cli-harness/adapters/registry.js",
    "roots": "lib/codex-bridge/cli-harness/adapters/*.js", "inputs": "lib/codex-bridge/cli-clients/*.json" }`:
    every adapter module and its transitive imports join the closure (24 modules today, vs 18 by
    literal imports alone), and the `cli-clients/*.json` files — whose `runtime_kind` decides
    dispatchability outside the import graph — are digested as inputs too. The digest is computed
    by `scripts/cli-surface.mjs --digest`
    over the **whole normalized module source** (TypeScript printer output, comments and whitespace
    normalized). The block also pins `"closure": [ …paths… ]` so a module entering or leaving the
    closure is itself a diff. The contract test recomputes and compares: any change to any module
    in the closure fails with "contract-relevant code changed in <path>: review the cases and run
    `cli-surface --digest --write`". `--write` updates **only** the digest and closure entries of
    the block (never a case), so the routine cost of an internal refactor is one command plus the
    doc diff appearing in review — which is exactly Goal 2's rule ("without the doc changing") made
    mechanical. Behaviour cases remain the check that the documented behaviour still holds; the
    digests are the check that undocumented behaviour cannot change unnoticed.
    Manual exemptions (`"manual": { "reason", "region_digest" }`) stay for handlers the extractor
    cannot follow, bound to the digest of the opaque region.
    **Negative controls for completeness:** temp copies of the closure with (a) one new
    `args.newFlag` read in a handler, (b) one new stdout key, (c) **the `--format text`
    counterexample**, (d) **a changed top-level constant** (`MESSAGE_ID_RE` accepting one more
    spelling), (e) **a changed imported producer** (`mcpCallConfig` in `models.js` adding a field
    for one model), (f) **a changed adapter reached only through the registry** (`agy.js`),
    (g) **a changed registry input** (`cli-clients/agy.json` `runtime_kind`), and (h) **a new
    unhandled computed import** added to a closure module must each fail with the document
    unchanged — (a) and (b) via the uninventoried-surface check, (c)–(g) via the module/input
    digests, (h) via the unresolved-module-load check. This is what makes "any change"
    detectable: each documented variant is exercised, new extractable surface cannot appear
    unnoticed, and any code that can influence the CLI's behaviour cannot change silently.
  - `wrapper`: runs the wrapper with the fake `codex`/`agy` on PATH for each documented exit path
    (usage, 74 via unwritable status path, 78 via bad model-role, HUP/INT/TERM via signals, child
    passthrough) and diffs the status-file field set.
  - `doctor`: runs `bin/codex-paired-doctor --json` and diffs envelope + check names; runs it
    without `--json` and asserts the human contract (one line per check starting with its status
    token; exit 0 when no `fail`, exit 1 with a forced `fail` — e.g. `CLAUDE_PLUGIN_ROOT` pointed
    at an empty dir).
  - `project-config`: **characterization tests** against the *existing* loader
    (`loadProjectConfig`): every permissive behaviour listed in the block is exercised, and the
    error codes and their precedence are asserted; the embedded JSON Schema is validated against
    the loader's accepted fixtures (all accepted fixtures must validate; every rejected fixture must
    fail with the documented code). No runtime change to the loader.
  - `skills`: extends `tests/skills/skill-structure.test.js`: command names come from
    `commands/<name>.md` filenames, arguments from each command's `argument-hint`, and skill inputs
    from the skill body's input section (no frontmatter args exist).
  - **Negative controls:** for every section, one test tampers a copy of the block (renames a
    field, drops an exit code, changes a type) and asserts the comparator reports the drift; and
    for `cli-verbs` and `wrapper` one control runs a case against a **tampered implementation**
    (a temp copy of `cli.js` / the wrapper with one field renamed / one exit code changed) and
    asserts the case fails. Comparator sensitivity and implementation sensitivity are both proven.

### 3. Support policy, doctor, CI (Goal 3)

- **Support policy**, stated identically in `package.json` (`engines`), README Prerequisites,
  `doctor`, and CI: *supported* = macOS and Linux on Node **≥ 20**, and CI tests **every released
  Node major ≥ 20, including the odd (non-LTS) lines** — today **20, 21, 22, 23, 24, 25, 26**; the
  matrix lists them explicitly. A structural test asserts README tested set == `ci.yml` matrix ==
  the contiguous range from the `engines` floor to the highest listed major (so an omitted major
  inside the range fails, not just an inconsistency between the two lists); bumping the top is one
  deliberate edit. Goal 3's "across the supported Node majors" is met literally. Windows (`win32`) and any other
  platform → `doctor` **FAIL**.
- `doctor`: one new check `platform` (FAIL unless `darwin`/`linux`). The Node floor reuses the
  **existing** `node` check (`bin/codex-paired-doctor` line ~42) — no second Node check; its
  `pass` detail names the CI-tested majors (the result framework has only `pass|warn|fail`).
- `.github/workflows/ci.yml`: `on: [push, pull_request]`; matrix `os ∈ {ubuntu-latest,
  macos-latest}` × `node ∈ {20, 21, 22, 23, 24, 25, 26}` (14 jobs; `fail-fast: false`); steps: `actions/checkout`, `actions/setup-node` with
  the matrix version and npm cache, **`npm ci`** (installs the dev deps from the lockfile), then
  `npm test` (which runs `typecheck` via `pretest`), `npm run test:shell`,
  `npm run test:fresh-clone`. Opt-in live tiers stay excluded.
- **Vendored tree vs dev deps.** `npm ci` rewrites `node_modules`, and the tracked tree today
  includes `node_modules/.package-lock.json` (npm regenerates it), while dev deps add `.bin/tsc`,
  `.bin/tsserver`, `typescript/`, `@types/`, and transitive `undici-types/`. Policy: the tracked
  (vendored) set is exactly the **runtime closure** of `dependencies` (`proper-lockfile` + its 3
  transitive deps); `node_modules/.package-lock.json` is **untracked** (removed from git, ignored);
  `.gitignore` ignores `node_modules/.bin/`, `node_modules/typescript/`, `node_modules/@types/`,
  `node_modules/undici-types/`. Two checks at two granularities: (1) **packages** —
  `scripts/check-vendored-deps.mjs` (run by `npm test` and CI) derives the tracked package roots
  and their versions from `git ls-files node_modules` (`node_modules/<pkg>/package.json` →
  `version`) and asserts the set equals the runtime closure resolved from `package-lock.json`
  (today: `proper-lockfile`, `graceful-fs`, `retry`, `signal-exit`) with matching versions — a dev
  dep can never sneak into the vendored set and a runtime dep can never go missing; the lockfile
  carries no file manifest, so this check does not claim file-level completeness; (2) **files** —
  after `npm ci` in CI, `git status --porcelain -- node_modules` must be empty, which catches a
  missing or modified internal file because npm's install re-materialises every file of the closure.
- `npm run test:shell` (new, `scripts/run-shell-tests.sh`): runs `tests/scripts/codex-exec-with-status.test.sh`,
  `doctor-models-check.test.sh`, `migrate-sidecars.test.sh` and **`fresh-clone-smoke.test.sh`**
  (the smoke's own negative-control test, including the stale-`--sha` case) under `bash`
  (`collect-test-files.mjs` only collects `.test.js`, so shell suites need this explicit list; a
  structural test asserts every `tests/scripts/*.test.sh` is either in the list or in the probe
  set), and treats
  `computer-use-availability.test.sh` as a **probe** with an expected outcome per OS (exit 0 on
  macOS, exit 1 elsewhere) — the script's existing behaviour is the contract. On macOS CI the
  suites run under `/bin/bash` (3.2) explicitly so bash-3.2 compatibility is exercised by the real
  interpreter; the structural grep for `declare -A` / `mapfile` / `${x,,}` / `${x^^}` in the
  user-facing scripts is kept as a fast guard. The dev-only release gate keeps its bash-4 note.
- README: CI badge; Prerequisites lists supported OS + Node with the tested set; the example path
  under "Local development" becomes relative.

### 4. Fresh-clone smoke (Goal 4)

`scripts/fresh-clone-smoke.sh` (`npm run test:fresh-clone`), bounded by a hard timeout (5 min,
via `node` wrapper since `timeout(1)` is not on macOS) and cleaning its temp dirs on every exit:

0. **Isolation.** The smoke exports `CLAUDE_PLUGIN_ROOT=<tmp>/clone` (doctor honours an inherited
   value — `bin/codex-paired-doctor` line 15 — so cwd alone is not enough), unsets every
   `CODEX_PAIRED_*` and `FAKE_*` variable inherited from the caller (env overrides outrank
   project config), sets `HOME=<tmp>/home` with a minimal `.gitconfig` (identity, `commit.gpgsign=false`),
   and a PATH of `<tmp>/bin:` + the system dirs only. Because that PATH would drop the Node under
   test (Homebrew/nvm/`setup-node` binaries are not in system dirs — `/usr/bin/env node` exits 127
   there), the smoke first captures `NODE_BIN=$(command -v node)` and `git` **before** isolation and
   symlinks both into `<tmp>/bin`; it then asserts `node --version` inside the isolated env equals
   the outer version (so CI runs the smoke on the matrix Node, not a system one). Same isolation
   pattern as `tests/scripts/doctor-models-check.test.sh` and the reviewer test setup.
1. `git clone --depth 1 file://<repo-root> <tmp>/clone` — the clone's tracked `node_modules` is
   what runs; nothing is installed.
2. Create `<tmp>/bin` and install the fixtures under the **executable names the plugin invokes**:
   `codex` → `tests/fixtures/fake-cli/codex.sh`, `agy` → `tests/fixtures/fake-cli/agy.sh`;
   prepend to PATH **before** anything else runs (doctor needs `codex` on PATH).
3. `bin/codex-paired-doctor --json` from the clone: exit 0, no FAIL check.
4. Temp project `<tmp>/proj` (git init, one commit) with `.codex-paired/project.json` setting
   `implement: { cli: "codex", model: … }` and `review: { cli: "agy", model: "gemini-3.8-flash-high" }`
   explicitly (defaults would resolve review to Codex).
5. Implementer cycle through the wrapper with `--model-role implement --repo-root --cwd`, where the
   fake codex runs in a new **commit mode** (`FAKE_CODEX_COMMIT=1`: writes `impl.txt`, `git add`,
   `git commit -m 'fake: implement'`, then emits its configured output; this is an addition to the
   fixture, existing modes unchanged). Assert: exit 0, status file `state: exited`, `exit_code: 0`,
   `cli: codex`, and `git log` in `<tmp>/proj` has the new commit.
6. Reviewer cycle: capture `IMPL_SHA=$(git -C <tmp>/proj rev-parse HEAD)` from step 5;
   `sidecar-init`; then `reviewer-thread-open --role review --sha $IMPL_SHA … --prompt-stdin` with
   the fake agy in a new **evidence mode** (`FAKE_AGY_RECORD=<file>`: before emitting its canned
   JSON it writes `{ cwd, head: $(git rev-parse HEAD), impl_txt_present }` to that file — an addition
   to the fixture, existing modes unchanged). Assert: `ok: true`, a `threadId`, the sidecar's
   `role_sessions["execution-reviewer"]` equals it, **the recorded `head` equals `IMPL_SHA` and
   `impl_txt_present` is true**, the recorded `cwd` is a throwaway checkout (not `<tmp>/proj`), and
   `<tmp>/proj` is unchanged (`git status --porcelain` empty apart from the sidecar). A deliberately
   stale `--sha` (the initial commit) must make this step fail — that is a test of the smoke itself
   in `tests/scripts/fresh-clone-smoke.test.sh`.
7. Print a one-line PASS summary; any failed assertion exits 1 with the step name.

This complements, and does not replace, the installed-smoke tier (`tests/installed-smoke/_README.md`:
real binaries, network, inference). Fresh-clone proves the *repository as cloned* works with the
fakes; installed-smoke proves the real CLIs work with the installed plugin.

## Frozen contracts (for the plan)

- `typecheck.allowlist.json` shape: `{ "version": 1, "files": string[] }` (sorted, repo-relative).
- `scripts/typecheck.mjs` exit codes: 0 pass; 1 tsc diagnostics; 2 allowlist/pragma inconsistency
  (missing file, missing pragma, unlisted `@ts-check` file).
- `docs/public-api.md` fenced blocks: ```` ```json public-api:<section> ```` with sections exactly
  `skills`, `cli-verbs`, `wrapper`, `doctor`, `project-config`, `sidecar`, `semver`.
- New doctor check name: `platform`. New npm scripts: `typecheck`, `test:shell`, `test:fresh-clone`.
- Fake codex new env: `FAKE_CODEX_COMMIT=1`. Fake agy new env: `FAKE_AGY_RECORD=<file>`.

## Risks

- `strict` JSDoc checking on old modules may need many annotations; the allowlist bounds the blast
  radius per slice, and a module is added only when it checks clean.
- `npm ci` in CI rewrites `node_modules`; the scoped assertion plus `check-vendored-deps.mjs`
  catch any divergence between the vendored runtime closure and the lockfile.
- The `cli-verbs` inventory is large (52 verbs); `scripts/cli-surface.mjs` seeds it once
  (flags / exits / stdout keys per verb), expectations are hand-completed, and the
  "uninventoried surface" check keeps it complete afterwards.
- The pinned closure is 24 of the 89 JavaScript modules under `lib/codex-bridge` today (plus the
  `cli-clients/*.json` inputs); changes to those require `cli-surface --digest --write` and show
  a doc diff. That is the accepted cost of Goal 2's literal rule; the skills' autopilot/SDD
  docs-update phase runs the command as part of any slice that touches a closure module.
- CI is 14 jobs; odd Node majors are EOL upstream but inside the declared `>=20` range, so they
  are tested until the support floor is raised in a future major.
- Pinning the public surface makes accidental changes loud on purpose; updating the doc is part of
  any intentional change.
