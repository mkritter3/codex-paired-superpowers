# v0.17.0 — Antigravity (`agy`) transport: Gemini as co-reviewer and code writer (design)

**Date:** 2026-09-17
**Status:** round 2 (revised after Gemini 3.8 round-1 REVISE; reviewer runs on `agy`, Codex is out of quota until 2026-09-19)
**Builds on:** v0.16.0 model roles (`docs/specs/2026-09-17-v0.16.0-model-roles-design.md`)

## Why now

- Codex hit its account usage limit mid-release; the user wants Gemini 3.8 to take **both** the
  co-reviewer seat and the code-writer seat until Codex replenishes, and to be able to switch
  between the two vendors with a config change afterwards.
- The Antigravity CLI (`agy` 1.2.5) has the shape the plugin needs (verified 2026-09-17):
  headless `-p` with `--output-format json` (returns `conversation_id`, `response`, `status`,
  `usage`, `denied_actions`), resumable conversations (`--conversation <id>` / `--continue`),
  `--model`, `--sandbox`, `--add-dir`, `--dangerously-skip-permissions`, `--mode plan`.
- Observed constraints that shape the design:
  - Effort is **inside** the model id for Flash (`gemini-3.8-flash-high|medium|low`); `--effort`
    conflicts with those ids. Pro ids are `gemini-3.1-pro-high|low`.
  - Headless mode auto-denies file reads unless permissions are pre-approved;
    `--dangerously-skip-permissions` approves everything, and `--mode plan` does **not** stop
    writes once permissions are auto-approved (a write probe landed in the repo).
  - `agy` has no `-C <dir>`; the working directory is the process cwd.
  - Each call loads a large context (≈80–135k input tokens for trivial prompts).

## Design

### 1. Roles gain a `cli` (spec §1 of v0.16.0 extended)

```js
MODEL_ROLE_DEFAULTS.planning = { cli: 'codex', model: 'gpt-6-astra', effort: 'xhigh' } // etc.
VALID_CLIS = ['codex', 'agy'];
```

- `validateModelsBlock` accepts `cli` (∈ `VALID_CLIS`); env override `CODEX_PAIRED_CLI` (all
  roles) and `CODEX_PAIRED_CLI_<ROLE>`; `sources[role].cli` tracked like the other fields.
- **Effort for `agy`.** For `cli: 'agy'` the `model` is the **full catalog id** including its
  effort suffix (e.g. `gemini-3.8-flash-high`); the role's effective `effort` is **derived from
  the suffix** (`-low|-medium|-high`) and **overrides whatever effort was inherited from a lower
  layer** (so `{ "planning": { "cli": "agy", "model": "gemini-3.8-flash-high" } }` works even though
  the built-in planning default is `xhigh`). Only an `effort` set **in the same layer as the agy
  model** (same project block or same env level) must equal the suffix; otherwise
  `models-config-malformed`, detail names both. A `cli: 'agy'` model without a recognised suffix
  is `models-config-malformed`. Rationale: `agy` rejects `--effort` combined with a suffixed id,
  and Pro ids only offer `low|high`; deriving from the id keeps one truth. `VALID_EFFORTS` is
  unchanged for Codex. `sources[role].effort` reports `derived` for agy roles.
- New exports:
  - `cliExecArgs(role, roles)` → `{ cli, command, args, insertAfter }`:
    codex → `{ cli:'codex', command:'codex', args:['-m',model,'-c',`model_reasoning_effort=${effort}`], insertAfter:'exec' }`;
    agy → `{ cli:'agy', command:'agy', args:['--model', model], insertAfter:null }` (insert right
    after the command token).
  - `mcpCallConfig(role, roles)` throws `models-config-malformed` ("role X uses agy; the Codex MCP
    tool cannot open an agy thread — use reviewer-thread") when `cli !== 'codex'`.
  - `harnessModelOptions(phase, ...)` returns `cli` too; the harness passes model options to
    whichever adapter the role's `cli` names.
- CLI: `model-role --format flags` prints the CLI-specific flags; `--format json` adds `cli`,
  `command`, `insertAfter`; `--format mcp` exits 2 for non-codex roles with the message above.
  `model-roles` output includes `cli` per role.

Switching examples (Goal 1):

```json
{ "models": {
    "review":    { "cli": "agy", "model": "gemini-3.8-flash-high" },
    "planning":  { "cli": "agy", "model": "gemini-3.8-flash-high" },
    "implement": { "cli": "agy", "model": "gemini-3.8-flash-high" },
    "implement_fallback": { "cli": "agy", "model": "gemini-3.1-pro-high" } } }
```
```bash
CODEX_PAIRED_CLI=agy CODEX_PAIRED_MODEL=gemini-3.8-flash-high claude   # everything on Gemini
```

### 2. Wrapper: CLI-aware `--model-role` (Goal 3)

`scripts/codex-exec-with-status.sh` (name kept for compatibility; it is the implementer wrapper):

- Resolves via `model-role --format json`; reads `cli`, `args`, `insertAfter`.
- **Command token:** the wrapper skips leading `env`/`nohup`/`VAR=value` tokens and compares the
  **basename** of the next token with the resolved `command` (`/opt/homebrew/bin/agy`,
  `./node_modules/.bin/codex` and bare `agy` all match). A mismatch (a role on `agy` wrapping
  `codex exec`, or vice versa) is 78 `model-role-conflicting-args` ("config says `<cli>`, command
  runs `<basename>`") — the config and the command disagree and the orchestrator must re-read
  the role.
- **Insertion:** codex → after the first `exec` token following the command token (as today);
  agy → immediately after the command token; missing `exec` for codex → 78 as today.
- **Conflict scan per CLI:** codex rules unchanged; agy rejects `--model`, `--model=*`,
  `--effort`, `--effort=*` (flag-shaped only; scan stops at `--`).
- **`--cwd <dir>`** (before `--`): the wrapper `cd`s there before spawning; required for `agy`
  (no `-C`), optional for codex. Status file gains `cwd`.
- **Orchestrator selection (the missing half of Goal 3).** Autopilot Phase B.4, B.6 (rungs 1–2),
  Phase C fix passes, and the interactive Step A no longer hard-code `codex exec`. They run
  `model-role --role <implement|implement_fallback> --format json`, read `cli`, and compose the
  locked invocation for that CLI (both are given in the contract doc); the wrapper's mismatch
  check is the safety net, not the selection mechanism. The Sonnet rung is unchanged. The
  `<implementation prompt>` template is CLI-independent.
- **`--print-timeout`:** set to the role's `codex_dispatch.max_runtime_ms` (default 2 h). On
  timeout `agy` exits non-zero with a JSON body whose `status` is not `SUCCESS`; the wrapper's
  terminal status then carries that exit code and the completion classifier treats it as
  `failed` (fallback), exactly like a codex non-zero exit. The orchestrator's own
  `max_runtime_ms` kill remains the outer bound.
- **Trust boundary (documented in the contract):** `--dangerously-skip-permissions` with
  `--add-dir <repo>/.git` lets the implementer run shell commands and write under the shared
  `.git` (needed to commit in a worktree). That is the same trust Codex `workspace-write` +
  `--add-dir` already has; it is not a sandbox against a hostile model. The contract states it
  plainly and forbids granting `--add-dir` beyond the repo's `.git`.
- Locked `agy` implementer invocation (contract doc):

```bash
scripts/codex-exec-with-status.sh <status-file> --model-role implement --cwd <worktree> -- \
  agy -p "<implementation prompt>" --sandbox --dangerously-skip-permissions \
      --add-dir <repo-root>/.git --output-format json --print-timeout 2h </dev/null
```

  `--sandbox` keeps terminal restrictions on; `--dangerously-skip-permissions` is what lets a
  headless run edit and commit (verified); `--add-dir <repo>/.git` is the worktree-commit fix
  carried over from v0.16.0; `--output-format json` gives the orchestrator `status`,
  `denied_actions` and `conversation_id` for the dispatch record. The prompt template and commit
  conventions are unchanged; the completion classifier reads the same status file.
- Fan-out (`two-disjoint`) and hybrid members stay Codex-only in this release (see Out of scope):
  `adapter: agy-cli` is **not** accepted by the frontmatter parser or `member-id.js`
  (`ALLOWED_CLI_KINDS` unchanged), and `dispatchCodexCliImplementer` is not generalised. A plan
  that names an agy member fails validation with the existing `implementer-directive-malformed`.

### 3. `agy` harness adapter (Goals 2, 5)

`lib/codex-bridge/cli-harness/adapters/agy.js` + `cli-clients/agy.json` (the `gemini.json`
placeholder is deleted; ladders say `agy`):

- `dispatch(systemPrompt, userPrompt, options)`; modes `reviewer` (default) and `implementer`.
- Composes `agy -p <prompt> --output-format json --model <m> [--conversation <id>] [--sandbox]
  [--dangerously-skip-permissions] [--add-dir ...]`. The prompt is passed as the `-p` argument
  (stdin is closed); system+user prompt are concatenated as for codex.
- Reviewer mode always passes `--sandbox --dangerously-skip-permissions --mode plan` (reads are
  otherwise auto-denied — verified) and **requires `options.cwd`**, which the caller sets to a
  throwaway checkout (§4). There are exactly two callers, and both own the checkout lifecycle:
  `reviewer-thread.js` (§4) for the paired thread, and `dispatchReviewerViaHarness` for domain
  panelists — when the resolved `cli` is `agy` it wraps the dispatch in `withReviewCheckout`
  (overlaying the request's `specPath` and any `request.overlayPaths`) and passes the checkout
  as `cwd`. No other code path may call the agy adapter in reviewer mode without a cwd.
- Parses the JSON: `responseText = response`, `sessionId = conversation_id`,
  `adapterMeta.status`, `adapterMeta.denied_actions`, `adapterMeta.usage`; `status !== 'SUCCESS'`
  → `exit 1` + warning `agy-status:<status>`; a non-empty `denied_actions` → warning
  `agy-denied:<names>`. Same timeout/abort/`onSpawn`/process-group semantics as the codex adapter
  (shared helper extracted, not copied).
- `harness.dispatch({ cli:'agy', variant })` works today via the registry; `variant` maps to
  `--mode plan` (read-only intent) for reviewers.

### 4. Reviewer thread on `agy` (Goal 2) and the throwaway checkout (Goal 4)

New `lib/codex-bridge/reviewer-thread.js`:

- `openReviewerThread({ role, specPath, repoRoot, prompt, sha })` and
  `continueReviewerThread({ role, specPath, repoRoot, prompt, sha })`. For `cli: 'codex'` they
  throw `reviewer-thread-codex-uses-mcp` (skills keep calling the MCP tool). For `cli: 'agy'` they:
  1. resolve the role (`resolveModelRoles`), 2. create a detached throwaway checkout via
  `withReviewCheckout(repoRoot, { sha, overlayPaths }, fn)` in `lib/codex-bridge/worktree.js`
  (`git worktree add --detach <tmp> <sha>`, default `sha` = `HEAD` of `repoRoot`; then every
  path in `overlayPaths` — the spec, the plan, and any other artifact the caller names — is
  copied from the user's tree into the checkout so **uncommitted artifacts under review are on
  disk for the reviewer's audit**; paths must be relative and inside the repo), 3. run the harness
  `agy` adapter in reviewer mode with `cwd = checkout`, `--conversation` when continuing,
  15-minute `timeout_ms`, 4. remove the checkout (always, in `finally`, via `git worktree remove
  --force` + prune), 5. on open, persist the conversation id via `setCodexThreadId(specPath,
  { role: key, newThreadId, reason: 'opened', threadConfig: { role, cli:'agy', model, effort } })`
  where `key` is `paired-reviewer` for `planning` and `execution-reviewer` for `review`.
  Returns `{ threadId, content, usage }`. Default `overlayPaths` = `[specPath]` plus the plan
  path when the caller passes one.
- The reviewed artifact **also** travels inside the prompt (spec text, plan text, diff), so the
  reviewer sees exactly what Claude sees; the overlaid checkout is what lets it grep/read the
  codebase and verify cited paths without touching the user's tree. `git status --porcelain` of
  the user's tree is asserted unchanged after each turn (test).
- `setCodexThreadId` validates `threadConfig.cli` (∈ `VALID_CLIS`) when present; `getThreadConfig`
  returns `cli: 'codex'` for entries and legacy sidecars that lack it (v0.16.0 compatibility), so
  recovery of an existing Codex thread is unchanged.
- CLI verbs so skills can drive it from bash:
  `reviewer-thread-open --role <planning|review> --specPath <p> --repoRoot <r> [--sha <s>] --prompt-stdin`
  and `reviewer-thread-reply --role ... --prompt-stdin`; both print `{ threadId, content }` JSON.
- Thread loss: an `agy` reply whose JSON reports a missing conversation (`status !== 'SUCCESS'`
  with the error naming the conversation id) is classified stale by a new
  `isStaleAgyResponse`; `recoverStaleThread` gains a `deps.openFn` path for `agy` (it already
  takes `codexFn`), re-seeds with `composeSeedPrompt` at the thread's recorded config, and rotates
  the id. `thread_config[key].cli` decides which path recovery takes.
- Skills (`brainstorming`, `writing-plans`, `subagent-driven-development`, `autopilot`,
  `systematic-debugging`, `test-driven-development`, `execution`) gain one branch at each
  thread-opening / reply site: "if `model-role --role <r> --format json` says `cli: agy`, use
  `reviewer-thread-open/-reply` instead of the MCP tool". Everything else (round logging,
  audits, `--headSha`, verdict parsing) is unchanged because both paths return the same
  `{ threadId, content }` shape.

### 5. Availability + doctor (Goal 6)

- `cli-clients/agy.json`: `command: agy`, `auth_probe: { args: ['models'], timeout_ms: 15000 }`
  (lists models only when signed in and the API is enabled — verified both failure modes print
  actionable errors), `permissions: { 'read-only': ['--mode','plan'], 'write-allowed': ['--dangerously-skip-permissions'] }`.
- `doctor` `models` check: for roles with `cli: agy`, skip the Codex catalog and instead WARN if
  the configured id is not in `agy models` output (cached 1h like the availability probe); PASS
  with "agy not installed; Gemini roles unverified" when `agy` is absent and no role uses it,
  WARN when a role uses it and it is absent.
- The availability report lists `agy` (replacing the never-implemented `gemini` row).

## Out of scope
- **Fan-out / hybrid members on `agy`** (`adapter: agy-cli`, `dispatchCliImplementer`
  generalisation, `member-id.js` allowlist): deferred to a later release; this one unblocks the
  paired reviewer, single-implementer dispatch, fix passes and domain panels.
- An MCP server for `agy` (none exists); the Codex MCP path is untouched.
- Mixed-vendor panels beyond what the ladders already allow.
- Changing defaults: Codex stays the default CLI for all four roles.
- Cost controls for `agy`'s large per-call context (documented, not mitigated).
