# v0.19.0 — Review panel and orphaned-checkout reaping: implementation plan

**Spec:** `docs/specs/2026-09-18-v0.19.0-review-panel-design.md` (approved unanimously by the
three-voice planning panel — Claude, Codex GPT-6 Astra xhigh, Gemini 3.8 Flash high — after 4 rounds)
**Date:** 2026-09-18
**Status:** round 1 (plan draft)

Already landed ahead of this plan: **WI-0** (`53e8900`), the removal of `withReviewCheckout`'s
repository-wide `git worktree prune`, because it was a live bug in shipped code.

Six work items in two independent lanes, joined at the end:

- **Panel lane:** slice 1 → slice 2 → slice 3
- **Checkout lane:** slice 4 → slice 5
- **Join:** slice 6 (skills, docs, contract, version), after all of the above.

slice 1 and slice 4 are disjoint on **Files:** and run in parallel; so do slice 2 and slice 5 once their
predecessors land. Red first everywhere. Writer: Codex at the `implement` role via the wrapper in a
worktree (`--add-dir <repo>/.git`); slice 6 is Claude-authored. Review: the standard lane — Claude
first, then the `review` role — because every item touches `lib/`, `scripts/`, `skills/` or a
contract document. Closure digests (`cli-surface.mjs --digest --write`) are refreshed before
verification in any item that touches a pinned module.

Shared conventions: ESM, Node ≥ 20, no new dependencies; error codes kebab-case on `err.code`; a
work item edits only its **Files:** (else report `NEEDS_CONTEXT`); commit subjects
`<type>(slice:N): …`; `npm test` green before done; every new module owner joins the typecheck
allowlist with `// @ts-check`.

## Frozen contracts (consumed across items)

- **Config** (slice 1): `review_panel: { planning?: Entry[], review?: Entry[] }`, `Entry = { cli:
  'codex'|'agy', model?: string }`. Resolved roster entry: `{ member_id, cli, model, effort }`,
  `member_id = "<cli>:<model>"`. Absent phase ⇒ `[{ cli: <role's cli> }]`. Errors:
  `models-config-malformed` with a path. Env: `CODEX_PAIRED_REVIEW_PANEL_PLANNING`,
  `CODEX_PAIRED_REVIEW_PANEL_REVIEW` (comma-separated CLIs).
- **Resolver** (slice 1, `lib/codex-bridge/review-panel.js`): `resolveReviewPanel({ phase, repoRoot,
  env }) → { roster, warnings }`; `warnings` includes `self-review:<member_id>` when a member's model
  equals the `implement` role's model.
- **CLI verb** (slice 1): `review-panel --phase planning|review --repoRoot <repo> [--format json]`;
  stdout `{ phase, roster, warnings }`; exit 0; exit 2 on usage or config error.
- **Verdict** (slice 1): `parseVerdict` returns `version: string | null` (quotes and surrounding
  whitespace stripped); `null` when absent. Existing fields unchanged.
- **Sidecar** (slice 2): top-level `panel_roster: { [phase]: RosterEntry[] }`; round fields
  `panel?: [{ member_id, cli, model, version, status, thread_or_conversation }]`,
  `claude_version?: string`. Shared validator `validatePanelRound(sc, round) → void` (throws
  `panel-round-invalid` with a reason) called by **both** `appendRound` and
  `appendRoundWithAudits`. `setPanelRoster(specPath, phase, roster)`; changing a persisted roster
  throws `panel-roster-changed`.
- **Panel runtime** (slice 3, `lib/codex-bridge/review-panel-run.js`): `runPanelRound({ phase, round,
  artifact: { version }, prompt, roster, claudeVerdict, previous }, deps) → { status:
  'SHIP'|'REVISE', members: [...], blocking: [...], deferred: [...] }`; `composeGeminiReplay({ goals,
  round, unresolved, previousRound }) → string`, throws `panel-replay-overflow` over 12,000 chars.
  Halts: `panel-member-unavailable`, `panel-unsupported-route`.
- **Markers** (slice 4, `lib/codex-bridge/checkout-markers.js`): `writeOwnershipMarker(worktreePath,
  { kind, run_id, base, overlays? })`, `writePreservationMarker(worktreePath, { reason, run_id })`,
  `readMarkers(worktreePath) → { ownership: object|null, preservation: object|null }`. Files:
  `<worktree git-dir>/codex-paired.json`, `<worktree git-dir>/codex-paired-keep.json`.
- **Ownership discovery** (slice 4, `scripts/lib/process-ownership.mjs`, extracted from the smoke):
  `findProcessesUnder(rootReal) → { pids: number[], complete: boolean, gaps: string[] }`.
- **Reaper** (slice 5, `lib/codex-bridge/checkout-reaper.js`): `inventoryCheckouts({ repoRoot, tmpDir,
  now }) → Entry[]` with `class: 'not-ours'|'preserved'|'candidate'`, `kind`, `age_ms`, `keep:
  string[]` (conditions that keep it); `reap({ repoRoot, apply }) → { removed, kept }`. CLI verb
  `worktree-reap [--apply] --repoRoot <repo>`; exit 0; exit 2 usage. Doctor check name `worktrees`.

## Slice 4: ownership and preservation markers, ownership-discovery completeness

**Domain:** ai-harness
**Validation:** critical
**Files:**
- lib/codex-bridge/checkout-markers.js
- lib/codex-bridge/worktree.js
- lib/codex-bridge/implementer/worktree-fanout.js
- scripts/lib/process-ownership.mjs

- tests/codex-bridge/checkout-markers.test.js
- tests/codex-bridge/worktree.test.js
- tests/codex-bridge/implementer/worktree-fanout.test.js
- tests/scripts/process-ownership.test.js

### Tasks
1. `checkout-markers.js` per the contract; the git-dir is resolved with `git rev-parse --git-dir`
   inside the checkout; writes are atomic (temp + rename); `readMarkers` returns `null` for a missing
   or unparseable marker (unknown ⇒ not ours).
2. `worktree.create` writes an ownership marker (`kind: implementation`) **only on the path that
   creates** the checkout; the idempotent return of an existing checkout never stamps one and never
   touches a preservation marker. `withReviewCheckout` writes `kind: review` with the exact
   `overlays` list before invoking the callback.
3. `worktree-fanout.js`: `createImplementerWorktrees` writes `kind: fanout`;
   `cleanupImplementerWorktrees({ keepForensics: true })` writes a preservation marker instead of
   returning silently.
4. Extract the smoke's ownership discovery into `scripts/lib/process-ownership.mjs` with explicit
   completeness (`complete: false` and a gap entry on a missing tool or any permission error); the
   smoke uses the extracted module with identical behaviour (its existing tests are the guard).
5. Tests: each creator writes the right marker; idempotent `create` on an unmarked existing checkout
   leaves it unmarked; an existing preservation marker is never overwritten; keepForensics writes
   the marker; `readMarkers` on missing/garbage files; discovery reports incomplete on an injected
   permission error.

### Tests required
Markers (≥ 8), creators (4), discovery completeness (3); existing worktree and smoke suites green.

## Slice 2: sidecar roster, shared unanimity validator, per-member audit gate

**Domain:** ai-harness
**Validation:** critical

### Tasks
1. `panel_roster` persistence and `setPanelRoster` (fixed for the life of a phase; a different roster
   ⇒ `panel-roster-changed`).
2. `validatePanelRound`, called from **both** `appendRound` and `appendRoundWithAudits`: in a phase
   with a roster, `round.panel` present with exactly one entry per roster member; every `version` and
   `claude_version` equal; `round.codex` derived (SHIP iff every member SHIP) and a disagreeing
   caller value rejected; an aggregate SHIP with any member REVISE rejected even with every audit
   present. With no roster, behaviour is byte-identical to today.
3. `assertRoundShipBacked`: on a panel SHIP, require a qualifying audit for `claude` and every roster
   `member_id`; unchanged with no roster.
4. `cli.js`: `sidecar-set-panel-roster` verb for the skills.
5. Tests for every rule on **both** write paths (the existing two-path pattern), plus unchanged
   legacy behaviour.

### Tests required
Roster (3), validator rules × 2 paths (≥ 14), audit gate (4), legacy unchanged (2).

**Domain:** ai-harness

### Tasks
1. Inventory from `git worktree list --porcelain` plus unregistered `cps-review-*` directories;
   classification not-ours / preserved / candidate from the markers.
2. Candidate conditions exactly as spec §6, re-evaluated immediately before each removal:
   not in use (incomplete discovery ⇒ keep); `HEAD` reachable from another ref; cleanliness via
   `git status --porcelain --untracked-files=all` plus `git ls-files --others --ignored
   --exclude-standard` (implementation/fan-out: nothing but regenerable ignored paths; review: only the
   recorded overlays, each byte-identical to the user's copy); age by the marker's `created_at`.
3. Stale entries removed one at a time with `git worktree remove --force <path>` only when ours and
   reachable; `git worktree prune` is never called.
4. `worktree-reap` verb (dry run default, `--apply`), and the doctor `worktrees` check (pass/warn,
   never fail; "not ours" listed for information; pre-v0.19.0 leftovers under `.git-worktrees/` and
   `.codex-paired/worktrees/` flagged as probable).
5. Tests, all in scratch repositories: each class; each keep condition independently; untracked
   files hidden by `status.showUntrackedFiles=no` still keep a checkout; a review checkout differing
   only by its overlays is reapable, one with any other change is kept; mixed safe/unsafe stale
   entries — the safe one removed, the unsafe one survives; incomplete discovery keeps everything;
   a user-created worktree is never touched; re-evaluation at removal time (a condition that turns
   false between listing and removal keeps the checkout).

### Tests required
Reaper (≥ 16), verb (3), doctor check shell cases (3).

## Slice 3: panel runtime

**Domain:** ai-harness
**Validation:** critical
**DependsOn:**
- slice-1
- slice-2
**Files:**
- lib/codex-bridge/review-panel-run.js
- lib/codex-bridge/panel/dispatcher.js
- typecheck.allowlist.json
- tests/codex-bridge/review-panel-run.test.js
- tests/codex-bridge/panel/dispatcher.test.js

### Tasks
1. Parameterize `dispatchPanel` so the review panel can set its own minimum (1), maximum and
   per-member timeout; the expert panel's defaults and behaviour are unchanged (its tests guard it).
2. `runPanelRound`: parallel dispatch of every roster member through injected transports; strict
   unanimity reducer (new, not the degraded-quorum aggregator); member failure of any kind —
   unavailable, timeout, parse failure, missing or wrong `version` — throws
   `panel-member-unavailable` naming the member; a round never decides with fewer voices.
3. `composeGeminiReplay` per the contract: unresolved blocking findings first, then the previous
   round's labelled findings, earlier resolved ones as a count; complete-payload budget 12,000
   characters; overflow throws, never truncates.
4. `assertPanelRouteSupported({ phase, route, roster })`: a multi-member `review` roster on the
   two-disjoint or hybrid route throws `panel-unsupported-route`.
5. Tests with injected transports (no live providers): unanimity (all SHIP ⇒ SHIP; any REVISE ⇒
   REVISE); independence (no member's input contains another member's current-round verdict); each
   failure mode halts; version mismatch halts; replay budget across rounds 1–7 with varying findings
   never exceeds 12,000 characters; overflow throws; unsupported routes halt; a one-member roster
   behaves exactly like today's single reviewer.

### Tests required
Runtime (≥ 14), dispatcher parameterization (3); expert-panel suites unchanged.
