**Spec:** `docs/specs/2026-09-18-v0.19.0-review-panel-design.md` (approved unanimously by the
three-voice planning panel — Claude, Codex GPT-6 Astra xhigh, Gemini 3.8 Flash high — after 4 rounds)
**Date:** 2026-09-18
**Status:** round 3 (revised after the panel's plan rounds 1–2)

Already landed ahead of this plan: the removal of `withReviewCheckout`'s repository-wide
`git worktree prune` (`53e8900`), because it was a live bug in shipped code.

## Execution order

Six slices, run **strictly in sequence**: 1 → 2 → 3 → 4 → 5 → 6. The round-1 draft claimed two
parallel lanes; that was wrong. Every slice that adds a CLI verb or edits a module in the CLI's
pinned import closure must update `docs/public-api.md` in the same slice (the digest refresh
rewrites it, `cli-surface.mjs --digest --write` refuses an uninventoried verb, and the contract test
compares the full verb inventory), and most slices also touch `lib/codex-bridge/cli.js` and
`typecheck.allowlist.json`. With those shared, the scheduler serializes them anyway, so the plan says
so.

Red first everywhere. Writer: Codex at the `implement` role via the wrapper in a worktree
(`--add-dir <repo>/.git`); slice 6 is Claude-authored. Review: the standard lane (Claude first, then
the `review` role). Closure digests are refreshed before verification in every slice that touches a
pinned module. Files marked *(new)* in a slice's task text are created by that slice; the **Files:**
blocks list bare paths only, because the plan parser keeps annotations as part of the path.

Shared conventions: ESM, Node ≥ 20, no new dependencies; error codes kebab-case on `err.code`; a
slice edits only its **Files:** (else `NEEDS_CONTEXT`); commit subjects `<type>(slice:N): …`;
`npm test` green before done; new modules join the typecheck allowlist with `// @ts-check`.

## Who dispatches what (architecture)

**Codex panel members are called by the orchestrator, not by library code.** Codex reviewer threads
run through the Codex MCP tool, which only the orchestrator (Claude, following a skill) can call. So
a panel round is split:

1. **The skill** resolves the roster, computes V, composes one prompt per member, and dispatches all
   members **in the same turn**: each Codex member as its own MCP call (parallel tool calls), each
   agy member through the `review-panel-member` CLI verb run in the background.
2. **The library** owns everything that must be correct regardless of who dispatched: roster
   resolution, V, replay composition, verdict validation, the strict-unanimity reduction, per-member
   session identity, and persistence through the append gate.
3. `runPanelRound` is a **test helper only**, built from the same entry points production uses
   (`review-panel-member`'s function and `reducePanelRound`), so tests cannot pass on a path
   production never takes; production goes through the `panel-reduce` verb.

**V (artifact version)** is computed by the orchestrator, never by a member: `sha256:<hex>` of the
file bytes for a spec or plan, the commit SHA for code. The prompt states V verbatim and each member
must echo it in `version:`; the library normalizes quotes and whitespace before comparing. (In plan
round 1 one member returned a content hash and the other a commit SHA for the same artifact; stating
V removes that ambiguity.)

## Frozen contracts

- **Resolver** (slice 1, `lib/codex-bridge/review-panel.js`): `resolveReviewPanel({ phase, repoRoot,
  env }) → { roster, configured, warnings }`. `configured` is true only when `review_panel.<phase>`
  is present in the project file or the phase's env override is set. `roster` entries `{ member_id,
  cli, model, effort }`, `member_id = "<cli>:<model>"`. Unconfigured ⇒ `configured: false` and the
  single default member. Warnings include `self-review:<member_id>`. Errors `models-config-malformed`.
- **Roster activation rule:** a roster is persisted, and the panel contract (required `version`, the
  panel append gate) applies, **only when `configured === true`**. Unconfigured phases keep today's
  path byte for byte: no roster, no `version` requirement, the existing single-reviewer transport
  (spec §2.3; Goal 1). Explicitly configuring a one-member panel opts into the panel contract.
- **Verdict** (slice 1): `parseVerdict` returns `version: string | null`.
- **Round-phase mapping** (slice 2): `panelPhaseForRound(roundPhase) → 'planning' | 'review' | null`.
  Planning **reuses the sidecar's existing `DESIGN_PHASE_RE`**
  (`/^(?:spec|plan(?:-\d+)?|plan-slice:.+)$/`), so the dynamic family `plan-2`, `plan-3`, … that the
  budget pushes new logical plans onto is covered, not only literal `plan`. Review: `review-slice:*`
  and `docs-update`. Everything else → null. When a phase has a persisted roster, **every** round
  whose phase maps to it must carry a valid panel. Tests: a persisted planning roster with a
  `plan-2` round on **both** append paths (missing panel rejected, complete unanimous panel
  accepted), and an enumeration of every round-phase key the skills write.
- **Sidecar** (slice 2): `panel_roster: { planning?: RosterEntry[], review?: RosterEntry[] }`;
  round fields `panel?: [{ member_id, cli, model, version, status, session }]`, `claude_version?`;
  `validatePanelRound(sc, round)` (throws `panel-round-invalid` with a reason) called by **both**
  `appendRound` and `appendRoundWithAudits`; `setPanelRoster(specPath, phase, roster)`, a different
  roster ⇒ `panel-roster-changed`. **Audit sides** accept `claude`, `codex`, and a `member_id`
  matching `^(codex|agy):[A-Za-z0-9._-]+$`; `assertRoundShipBacked` on a panel SHIP requires a
  qualifying audit for `claude` and every roster `member_id`.
- **Per-member sessions** (slice 2): a Codex member's thread is stored at
  `role_sessions["<sidecarKey>:<member_id>"]` (`sidecarKey` is `paired-reviewer` for planning,
  `execution-reviewer` for review), so two Codex models get two threads. agy members store nothing:
  they open a fresh conversation every round.
- **Markers** (slice 3, `lib/codex-bridge/checkout-markers.js`): written into the worktree's private
  admin directory (`<common git dir>/worktrees/<name>/`), as `codex-paired.json` (ownership) and
  `codex-paired-keep.json` (preservation). `writeOwnershipMarker(worktreePath, { kind, run_id, base,
  overlays?, created_at? })` (`created_at` defaults to now); `writePreservationMarker(worktreePath,
  { reason, run_id })`; **`readMarkers({ repoRoot, adminDir })`**, taking the admin directory from the
  registry so it works when the checkout's own directory has been deleted, returns
  `{ ownership, preservation }`, each `{ state: 'absent' | 'valid' | 'invalid', value }`.
  Fail-closed classification: invalid ownership ⇒ not ours; invalid preservation ⇒ preserved.
- **CLI verb** `checkout-preserve --path <worktree> --reason <text> --run <id> --repoRoot <repo>`
  (slice 3): writes a preservation marker; exit 0; exit 2 on usage or a path that is not a registered
  worktree.
- **Ownership discovery** (slice 3, `scripts/lib/process-ownership.mjs`): `findProcessesUnder(rootReal)
  → { pids, complete, gaps }`.
- **Reaper** (slice 4, `lib/codex-bridge/checkout-reaper.js`): `inventoryCheckouts({ repoRoot, tmpDir,
  now }) → Entry[]` with `class`, `kind`, `age_ms`, `keep: string[]`; `reap({ repoRoot, tmpDir, now,
  apply })`; verb `worktree-reap [--apply] --repoRoot <repo>`. Doctor check `worktrees`.
- **Member availability** (slice 5): before a panel's round 1, every member is checked with the
  existing `detectAvailableCLIs` (binary present and auth probe passing); any failure halts with
  `panel-member-unavailable` naming the member.
- **Panel runtime** (slice 5): `reducePanelRound({ roster, version, claude, members })` → `{ status,
  blocking, deferred }`, throws `panel-member-unavailable` (a missing, failed or version-mismatched
  member); `composeMemberReplay({ goals, round, unresolved, previousRound })`, 12,000-char budget over
  the complete payload, throws `panel-replay-overflow`; verbs `review-panel-member` (one agy member,
  fresh conversation, returns `{ member_id, verdict, conversation_id, usage }`, exit 1 on member
  failure) and `panel-reduce` (reads member verdicts on stdin, prints the reduction, exit 1 on a
  halt). **Route preflight** `assertPanelRouteSupported({ repoRoot, split })` throws
  `panel-unsupported-route` when a **configured** `review` roster has more than one member and the
  split is `two-disjoint` or `hybrid-ui-backend`. `runSplit` does not create checkouts (its caller
  supplies fan-out worktrees through `workItem.worktrees`), so a guard there alone cannot promise
  "before any checkout exists". The preflight therefore runs at **every checkout-creating entry of
  those routes** — first thing in the fan-out creator `createImplementerWorktrees` and before
  `worktree.create` in the hybrid runner (`hybrid/runner.js`) — and again inside `runSplit` after
  normalization as defence in depth.
