## Frozen contracts (implemented in slice 1; consumed by 2–6)

`lib/codex-bridge/models.js` exports exactly:

```js
export const MODEL_ROLES = ['planning', 'review', 'implement', 'implement_fallback'];
export const MODEL_ROLE_DEFAULTS; // frozen: planning gpt-6-astra/xhigh, review gpt-6-astra/high,
                                  //         implement gpt-5.6-sol/high, implement_fallback gpt-6-astra/medium
export const VALID_EFFORTS = ['low','medium','high','xhigh','max','ultra'];
export const SAFE_TOKEN = /^[A-Za-z0-9._-]+$/;
export const CODEX_CLI_VALIDATED_VERSION = '0.153.4';
export class ModelsConfigError extends Error { code = 'models-config-malformed'; detail }
export function validateModelsBlock(block)           // null | { code:'models-config-malformed', detail }
                                                     // null/undefined/non-object/array → error (project-config treats null/undefined as ABSENT before calling this)
export function resolveModelRoles({ repoRoot = process.cwd(), env = process.env } = {})
                                                     // → { roles:{[role]:{model,effort}}, sources:{[role]:{model:'default'|'project'|'env', effort:...}} }
                                                     // throws ModelsConfigError; never partial
export function codexExecArgs(role, roles)           // ['-m', model, '-c', `model_reasoning_effort=${effort}`]; unknown role throws ModelsConfigError
export function mcpCallConfig(role, roles)           // { model, config:{ model_reasoning_effort } }
export function roleForThread(key)                   // 'paired-reviewer'→'planning', 'execution-reviewer'→'review', else 'planning'

export function harnessModelOptions(phase, { repoRoot, env, roles } = {})
                                                     // roles precomputed optional; else resolveModelRoles({repoRoot, env})
                                                     // → { modelRole, model, reasoningEffort, warning }
export function compareVersions(a, b)                // semver-ish numeric compare: <0, 0, >0
```

CLI (`lib/codex-bridge/cli.js`):

```
model-role  --role <r> [--repoRoot <dir>] [--format json|flags|mcp]   # default json
   json  → {"role","model","effort","sources":{"model","effort"}}
   flags → -m <model> -c model_reasoning_effort=<effort>            (single line, no quotes)
   mcp   → {"model":"...","config":{"model_reasoning_effort":"..."}}
   unknown role / config error → exit 2, EMPTY stdout, stderr names the error
model-roles [--repoRoot <dir>]  → {"roles","sources","validated_cli_version":"0.153.4"}
```

Types (`lib/codex-bridge/implementer/types.js`): `ImplementerDispatchInput` gains optional
`modelRole`, `model`, `effort`, `repoRoot` (absolute path; **required** by the direct-CLI
launcher/observer, which derive the attempt-evidence path from it), and
`onLaunched?: (snapshot: {model_role, model, effort, status_file?}) => Promise<void>|void`
(a dispatch fn calls it once the attempt's launch evidence exists — for wrapper-launched
transports, once the initial status file is written); `ImplementerDispatchResult` gains optional
`modelSnapshot: { model_role, model, effort } | null` and `attemptInFlight?: boolean` (set only by
an observer that timed out while the attempt's process was still alive; the result is otherwise the
complete `halted` shape). `__shapesForTests` gains
`dispatchInputOptionalProps: ['effort','model','modelRole','onLaunched','repoRoot']` and
`dispatchResultOptionalProps: ['attemptInFlight','modelSnapshot']` (five keys total).

Adapter (`cli-harness/adapters/codex.js`, implemented in slice 4 but frozen here so slice 2's
tests can rely on it): `options.signal` (an `AbortSignal`) aborts the child exactly like the
internal timeout path (SIGTERM → SIGKILL grace, process-group reap) and yields
`warnings: ['aborted']`, `exit: 130`; `options.onSpawn?: (pid: number) => void` is called
synchronously right after a successful `spawn()` with the child's pid (never called on
spawn failure).

Status classification (`lib/codex-bridge/dispatch-status.js`, slice 2) — **one ordered rule set**:
1. runtime exceeded → `timeout`
2. status object with `status:'blocked'` (any `exit_code`) → `blocked`
3. status object with `status:'needs-context'` (any `exit_code`) → `needs-context`
4. `exit_code === 78` → `config-error`
5. `transient:true` → `transient`
6. `exit_code === 0` (any `state`/`status`, incl. wrapper `state:'exited'` and legacy `status:'completed'`) → `completed`
7. `exit_code` a non-zero number → `failed`
8. status object with `exit_code == null` (nonterminal) → `transient` if `taskAlive` else `lost`
9. no status file → `transient` if `taskAlive` else `lost`
Hybrid's `classifyBackgroundStatus` delegates and then **maps `blocked`/`needs-context` to
`state:'failed'` with `haltReason:'hybrid-codex-backend-failed'`** (hybrid has no ladder; it halts
either way) so its existing exact-shape rows, including the blocked row, stay green.

Reviewer turn record (`sidecar.js` `appendReviewerTurnLocked` / `appendExpertTurnLocked`
whitelist): optional `model_role` (∈ MODEL_ROLES) and `model_role_warning` (non-empty string),
validated like `resolved_cli`. Producers set them from the request (slice 4).

Status file (wrapper): `{ state:'started'|'exited', exit_code:null|int, signal, started_at,
completed_at:null|iso, model_role?, model?, effort?, error? }`. `error` ∈
`model-role-resolution-failed | model-role-conflicting-args` when `exit_code === 78`.

Halt reasons (registered in slice 2 in both `halt-envelope.js` and `reviewer-archive.js`, all
terminal + PRESERVE): `model-role-resolution-failed`, `model-role-conflicting-args`,
`implementer-attempt-lost` (a direct-CLI attempt's evidence file says `running` but its pid is
gone, or says `launching` for longer than the launch grace — resume cannot observe it and must
not relaunch silently), `implementer-attempt-timeout` (the observer's `timeout_ms` elapsed while
the attempt was still alive).

Direct-CLI attempt evidence (written by `dispatchCodexCliImplementer`, slice 4; read by resume):
`<input.repoRoot>/.codex-paired/attempts/<implementerRunId>/<memberIdSlug>.json` =
`{ state:'launching'|'running'|'exited', pid:null|number, launched_at, spawned_at, completed_at,
exit_code, outcome, head_sha, changed_files, diff_hash, halt_envelope, model_role, model, effort }`.
Lifecycle: (1) `state:'launching'`, `pid:null`, snapshot, `launched_at` — written atomically
**before** the adapter spawns; this write triggers `onLaunched`; (2) the adapter's `onSpawn(pid)`
callback atomically rewrites it to `state:'running'`, `pid`, `spawned_at` — the **child pid is the
authoritative liveness handle**; (3) rewritten atomically to `state:'exited'` with the full
result on exit. `.codex-paired/` is already gitignored. Launch grace: an evidence file still
`launching` more than 60 s after `launched_at` is treated as lost.

Attempt state from events (`implementer/orchestrator.js`, slice 4): the member's **latest
lifecycle event** — `started | checkpoint | completed | failed | cancelled | halted`, ignoring
`mailbox_*`, `merge_*`, `merger_*`, `post_merge_review` — gives a provisional state:
none/`failed`/`cancelled`/`halted` → **new attempt candidate**; `completed` → **reuse** (result
rebuilt from the `completed` payload, no launch); `started`/`checkpoint` → **in flight** (observe,
never launch). **Observation halts are not attempt endings:** an observer result with
`attemptInFlight: true` (timeout while the child lives) is recorded as a `checkpoint`
`{ phase:'observation-timeout' }`, never as `halted`, so the member stays in flight. **Evidence
beats events:** before launching a new-attempt candidate the orchestrator reads the member's
attempt evidence file; if it is `running` with a live pid (or `launching` within grace) the
member is observed instead of launched. There is never more than one writer per member.
