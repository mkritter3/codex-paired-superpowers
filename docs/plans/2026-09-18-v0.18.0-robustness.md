# v0.18.0 — Robustness for other people's machines: implementation plan

**Spec:** `docs/specs/2026-09-18-v0.18.0-robustness-design.md` (double-SHIP'd, 7 rounds)
**Date:** 2026-09-18
**Status:** round 3 (revised after Codex plan-review rounds 1–2; planning thread `01a0b20c-453c-7273-a54e-c55d09ea59c3`)

Five slices, executed **1 → {2, 4} in parallel → 3 → 5**. Slice 1 lays the foundation (dev deps,
the typecheck runner, the shared typedefs, the vendored-deps check, the JSON Schema validator
dependency, the first checked owners, the bash-3.2 guard). Slices 2 (annotate the remaining
owners) and 4 (doctor `platform`, shell runner, fixture modes, fresh-clone smoke) are disjoint on
**Files:** and run in parallel worktrees after slice 1 lands. Slice 3 (public-API doc,
`cli-surface.mjs`, contract tests) runs after **both** 2 and 4 because it pins the final digests
of modules slice 2 annotates and documents the `platform` check slice 4 adds — no temporary
exemptions. Slice 5 (CI workflow, README/support policy, consistency tests, version bump, skill
wiring) is Claude-authored and last. Red-first everywhere. Implementer for slices 1–4: Codex at the
`implement` role via the wrapper in a worktree (`--add-dir <repo>/.git`). Reviewer: Claude first
(C0), then Codex on the execution thread; both SHIP the same commit (`--headSha`).
`buildDAG(planPath).ok === true` is checked before any dispatch.

Shared conventions: ESM, Node 20+; **three new dev dependencies only** (`typescript`,
`@types/node@20`, `ajv@8` for JSON Schema draft 2020-12 — dev-only, never vendored), no new
runtime dependencies; error codes are kebab-case on `err.code`; a slice edits only its **Files:**
(else report `NEEDS_CONTEXT`); commit subjects `<type>(slice:N): …`; `npm test` green (including
the `pretest` typecheck once slice 1 lands) before done. Base branch: `release/v0.18.0` (from
`main` @ 4537bf5).

**Worktree setup (every implementation worktree and the integration checkout, from slice 1 on):**
the checkout carries the vendored runtime packages but not the dev deps, so run `npm ci` in the
worktree before `npm test` (the existing whole-`node_modules` bootstrap refuses an existing
directory and is not used for this). The wrapper dispatch prompt for slices 2–4 includes this step.

**Sandbox note for the implementer:** inside the Codex sandbox, `tests/codex-bridge/app-launcher.test.js`
shows three `listen EPERM` failures (socket bind forbidden). They are environmental and ignored by
review; report them under `concerns`. Everything else must pass.

## Frozen contracts (implemented in slice 1; consumed by 2–5)

- `tsconfig.json`: `{ "compilerOptions": { "allowJs": true, "checkJs": false, "noEmit": true,
  "strict": true, "module": "nodenext", "moduleResolution": "nodenext", "target": "es2022",
  "types": ["node"], "skipLibCheck": true }, "include": [] }`. It is **not** meant to be run
  with bare `tsc -p` (an empty file set is TS18003); the runner reads it with `ts.readConfigFile`,
  injects the allowlist as `files` into the raw config **before** `ts.parseJsonConfigFileContent`,
  so a valid config parses without the empty-input diagnostic while option errors (e.g. TS5023)
  still fail the runner with exit 2 and the TS message; the parsed `fileNames` are the `rootNames`.
- `typecheck.allowlist.json`: `{ "version": 1, "files": string[] }` sorted, repo-relative.
- `scripts/typecheck.mjs`: exit 0 pass; 1 diagnostics; 2 configuration/allowlist/pragma
  inconsistency (invalid compiler options; missing file; missing pragma; unlisted `@ts-check`
  file in the effective program or under `lib/`, `scripts/`, `bin/`). Flags: `--allowlist <path>`
  (default `typecheck.allowlist.json`), `--root <dir>` (default repo root), `--tsconfig <path>`.
  Prints diagnostics as `path:line:col TSxxxx message`.
- `lib/codex-bridge/types.js`: `@typedef`s `ModelRole`, `RoleConfig`, `StatusFile`, `Sidecar`,

  `extra <pkg>@<v>` / `missing <pkg>@<v>` / `version <pkg> tracked=<v> lock=<v>`).

  `pretest` = `node scripts/typecheck.mjs && node scripts/check-vendored-deps.mjs && node scripts/check-bash32.mjs`,
  `test:shell` and `test:fresh-clone` (stubs in slice 1 printing `not implemented until slice 4`,
  exit 0; replaced in slice 4).

  `node_modules/typescript/`, `node_modules/@types/`, `node_modules/undici-types/`,
  `node_modules/ajv/` and ajv's transitive dev closure (`fast-deep-equal/`, `json-schema-traverse/`,

- Fake CLI additions (slice 4): `FAKE_CODEX_COMMIT=1` (writes `impl.txt`, `git add`, commits

- `docs/public-api.md` blocks (slice 3): ```` ```json public-api:<section> ```` with sections exactly

- `scripts/cli-surface.mjs` (slice 3): output `{ verbs: { <verb>: { flags, exits, stdoutKeys, unsupported } },

- New doctor check name (slice 4): `platform`. Doctor constant `TESTED_NODE_MAJORS="20 21 22 23 24 25 26"`.
- Digest refresh rule (slice 5 wires it into the skills; slice 3 documents it): a slice that

  **before** its verification run and commits the doc diff in the same commit that is reviewed
